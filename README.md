## 项目 1：OB5X ETF / 期货 / 期权多模块策略

`assignment2-etf-futures-options-strategy.ipynb` · 团队 2 人项目 · 约 3,900 行 Python

三个模块共用一条交易所连接、共享限频与仓位检查：

| 模块 | 逻辑 | 本次运行盈亏 |
|---|---|---|
| **ETF–股票篮子套利** | 依据一价定律，将 OB5X ETF 与整数篮子 `7 ASML + 1 AAPL + 1 SAP + 18 TSLA + 8 NVDA` 比价；价差覆盖成本时建仓 | +$17.20 |
| **ETF–期货基差交易** | 将 ETF 与期货统一折算为指数点，按基差偏离历史区间建对冲仓 | +$244.00 |
| **期权做市 + Delta 对冲** | 自同组期权反推隐含波动率，混合市场中间价与 Black–76 理论价定报价中心；用期货做 Delta 中性 | −$6.80 |

**自适应仓位分档**：按可执行价差强度与信号/价差比，选择 1 / 2 / 3 个篮子包，
并结合市场深度检查回退到较小档位，而非固定交易手数。

**实测结果（60 分钟连续运行）**
- 账户总盈亏 **+$254.40**
- 成交 751 笔，总交易量 11,152 units
- 账户盈亏区间 −$15.10 ~ +$259.50，峰值回撤 **$59.40**

**问题定位**：理论信号显示的利润在实测中未能稳定兑现。排查后确认**并非定价错误**，
而是市场上约 5 名活跃参与者持续竞争同一做市与相对价值机会，且更早进入订单队列，
导致同价位报价排队靠后、成交不足。据此调整报价与撤单逻辑。

## 项目 2：双挂牌股票做市与统计套利（个人作业）

`assignment1-dual-listed-market-making.ipynb`

针对在两地挂牌的同一标的 `ASML` / `ASML_DUAL`，组合三种策略：

1. **插值 Stellage 主动交易** —— 用 `stellage_targets(S)` 插值表把价差信号映射为连续目标仓位：
   价差小则仓位轻，价差接近历史极值则仓位最重；避免硬阈值造成的反复开平仓。
   仅当跨越买卖价差的成本能被均值回归收益覆盖时才触发（`MAX_STELLAGE_CROSS_COST`）。
2. **Crossed 纯套利** —— 订单簿短暂交叉时，按 `CROSSED_MIN_EDGE` 判定并捕捉无风险价差。
3. **被动做市** —— 以两只标的中间价的均值作为 `common_fair` 报价中心，
   并通过 `MAX_INVENTORY_SKEW` 随库存偏移双边报价，抑制逆向选择。
4. **Spill 对冲** —— `position_balancer` 监控净方向敞口（Position A + Position B），
   超过容忍度（10 lots）时以 IOC 单抹平，保持 Delta 中性。

**实测结果（60 分钟）**
| 指标 | 数值 |
|---|---|
| 盈亏 | +$25.70 |
| 成交量 | 4,319 lots |
| 发出订单 | 22,745（主动 IOC 925 / 被动限价 21,820） |
| 订单成功率 | 83% – 95% |
| 限频拦截 | 0 次 |
| 期末净敞口 | +2 lots |

**调试演进（三类导致单向亏损的逻辑缺陷）**

1. **自成交与超限** —— 早期版本只读持仓、未计入未成交挂单，导致突破仓位上限。
   改进：新增 `get_position_bounds()` 以"最坏情况持仓"计算边界，
   并在每次主动下单前执行 `cancel_all_quotes()` 清除过期挂单。
2. **符号错误锁死单向交易** —— 可卖数量计算写为 `max(0, worst_B - MAX_POS)`，
   在持仓为零时恒返回 0，使"买 A + 卖 B"方向被完全锁死，算法长期单向持仓。
   修正为 `max(0, worst_B + MAX_POS)` 后恢复双向能力。
3. **目标区间交集为空导致信号冲突** —— 早期分别计算买入/卖出价差的目标区间再取交集，
   忽略了下界可能大于上界（`L > U`）的情形，导致同时触发相互矛盾的信号。
   改进：统一为单一中间价价差信号 `S_mid = (mid_A - mid_B) / S_MAX`，从源头消除冲突。
